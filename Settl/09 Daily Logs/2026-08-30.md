## Problems & Solutions

- *Issue:* Passlib 1.7.4 threw an attribute warning with newer bcrypt 4.x.
  *Fix:* Switched to direct, standard `bcrypt` hashing in `auth_service.py` with zero warnings.
- *Issue:* Docker requirement removed for submission.
  *Fix:* Configured direct native Windows execution (Python 3.13 virtualenv + Node.js 22 npm) with unified `scripts/run_dev.py`.
- *Issue:* Supabase transaction pooler (port 6543) threw `DuplicatePreparedStatement` on startup.
  *Fix:* Set `prepare_threshold=None` in SQLAlchemy engine connect args for psycopg3.

## Decisions

- Next.js 15 + App Router + Tailwind CSS for rich modern frontend
- FastAPI + Pydantic v2 + SQLAlchemy 2.0 for high-performance API and ML readiness
- Native local execution without Docker
- Connected live to Supabase PostgreSQL (`aws-0-ap-south-1.pooler.supabase.com:6543`)
- Strict monetary representation in paise as `BIGINT` across all database columns and API contracts
- Deterministic baseline logic guarantees operational reliability even before LLM integration

## Things I Learned

- Operating invariant: **AI recommends; deterministic policy authorizes; Razorpay executes; verified webhook events confirm recovery.**
- Keeping numerical probability inside ML/risk scoring prevents hallucinations and ensures predictable policy gating.
- Razorpay Test Mode limit: 30 Payment Links per business, necessitating strict separation of the 5,000 synthetic event evaluation harness from the live test mode demonstration loop.
